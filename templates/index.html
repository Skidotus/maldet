{# ============================================================= What the project is ============================================================= #}

The project

A second opinion for
code you didn't write.

Developers clone, install and depend on public repositories every day, usually without reading them. Attackers know that and hide malware in packages, archives and install scripts. MalDet checks a repository for you before it reaches your machine.

Vulnerability verdict

Insecure coding patterns an attacker could exploit, such as injection, weak crypto or hard-coded secrets, plus known CVEs in the repository's pinned dependencies.

Malicious-pattern verdict

Signs that the code is meant to cause harm: malware signatures, obfuscated payloads, typosquatted package names and install-time hooks. It is scored separately, because a careless mistake and a deliberate attack are different risks.

Noise filtering with machine learning

Six engines on a large repository can produce tens of thousands of findings. A Random Forest classifier gives each finding a confidence that it is real, and that confidence weights the score instead of every alert counting the same.

Plain-English summary

A local language model explains the main findings in a short paragraph. It only explains the results. The risk levels are decided before it sees anything, and it may not change them.

How a scan runs

  1. 01
    FetchRepository metadata from the GitHub API, then a shallow clone.
  2. 02
    UnpackArchives are extracted, including password-protected ones.
  3. 03
    DetectSix engines inspect code, files and dependencies.
  4. 04
    TriageThe classifier separates likely-real findings from noise.
  5. 05
    ScoreTwo risk levels, from Safe to Critical, saved to your history.
